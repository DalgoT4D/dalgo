# Files

- [AI features: Chat with Data and ai-llm-service](ai-features.md) - How Dalgo's Chat with Data (Copilot) works end to end - the core/ai turn graph, SQL and platform-guide agents, SQL guards, human-in-the-loop approval, WebSocket consumer and webapp UI - and how it differs from the separate ai-llm-service that backs log and warehouse-result summarization.
- [Auth, orgs, roles and permissions](auth-orgs-permissions.md) - How Dalgo authenticates requests with JWT cookies, resolves the active OrgUser from the x-dalgo-org header, loads roles and permissions from seed fixtures into Redis, enforces has_permission and has_access, and models per-resource sharing and ownership.
- [Backend layers: API, core, schemas, models](backend-layers.md) - How the Django Ninja backend in backend/ddpui is layered (API to core to models, one way), how a request flows through it, how routers are mounted in routes.py, how api_response, exception handling and logging work, and which invariants are non-negotiable and why. Also records where the code deviates from the written rules.
- [Background work: Celery and Redis](background-work.md) - How the Dalgo backend runs asynchronous and scheduled work with Celery (Redis broker, RedBeat beat), how tasks report progress through Redis-backed helpers, how the webapp polls it, and how the Prefect webhook, TaskLock and stuck-lock cleanup behave.
- [Charts, dashboards and reports](charts-dashboards-reports.md) - How Dalgo's native visualization stack works end to end - chart query and ECharts config generation (including maps and pivots), dashboards with filters and dependent filter groups, public share links bounded by tokens, and report snapshots with comments, PDF export and email sharing. Also states plainly that report scheduling is only planned.
- [Ingestion (Airbyte)](ingestion.md) - How Dalgo manages Airbyte sources, destinations and connections through ddpui/ddpairbyte, turns each connection into OrgTasks plus Prefect deployments, discovers schema over a websocket, receives sync job stats via a webhook, applies post-sync column casts (ingest-cast), and exposes all of it in the webapp ingest UI.
- [Metrics, KPIs and alerts](metrics-kpis-alerts.md) - How reusable Metrics, target-tracked KPIs and cron-scheduled Alerts fit together in Dalgo, covering the models, services, REST APIs, the Celery dispatcher/evaluator, email and Slack delivery, webapp surfaces, and what the harness task lists say is built.
- [Orchestration (Prefect, prefect-proxy, webhooks)](orchestration.md) - How the Django backend schedules and runs pipelines through prefect-proxy and Prefect, how OrgTask/OrgDataFlowv1/TaskLock model them, how Prefect state changes return through a webhook to the Celery task handle_prefect_webhook, plus the job-runner image, the vendored prefect_airbyte package and how far the prefect-runner-migration plan is implemented.
- [Platform: Docker, compose and CI/CD](platform.md) - How Dalgo's per-service Docker images, the dev/staging/production compose stacks, the Prefect job-runner image, and the GitHub Actions workflows (per-service CI, docs, OpenWiki update, staging and production deploys) fit together.
- [Transformation (dbt, canvas, UI transform)](transformation.md) - How Dalgo gives each org a git-backed dbt workspace, lets users build dbt models on a visual canvas (CanvasNode/CanvasEdge with an advisory lock), publishes them through git, and runs them as Celery or Prefect dbt tasks.
- [Warehouses](warehouses.md) - How the backend reaches an organization's Postgres or BigQuery warehouse through WarehouseFactory.get_warehouse_client, how credentials are stored in Secrets Manager, how Postgres engines are pooled, why old_client must not be used, and which APIs and features consume warehouses.
- [Webapp architecture](webapp.md) - How the Next.js 15 App Router webapp is organised - routes, feature folders, the lib/api.ts fetch wrapper (cookies, x-dalgo-org, token refresh), SWR hooks, Zustand stores, middleware, WebSockets, PostHog analytics and the shared conventions from webapp/CLAUDE.md and .claude/rules.
